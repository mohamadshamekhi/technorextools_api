# پیاده‌سازی مرحله کاتالوگ — فاز ۱ (بک‌آفیس + فروشگاه)

مطابق بلوپرینت v0.3 (بخش‌های ۰۵، ۰۶، ۰۹ و ۱۹): درخت دسته‌بندی نامحدود، ویژگی داینامیک، واریانت رنگ، تصاویر، برند با نشان اصالت، فیلتر وجهی پایه، مرتبط‌ها، شگفت‌انگیز، دیتاشیت. تصاویر فقط با URL (بدون آپلود). اسکیمای Prisma دست نمی‌خورد (مدل‌ها کامل‌اند). بدون env جدید.

## ساختار فایل‌ها

```
src/modules/catalog/                    # هسته دامنه — @Global (مطابق الگوی AccessModule)
├── catalog.module.ts                   # export هر ۶ ریپازیتوری
└── repositories/
    ├── category.repository.ts          # CRUD + درخت + findByIdWithCounts
    ├── attribute-group.repository.ts   # CRUD + findByCategory
    ├── attribute.repository.ts         # CRUD + findByGroupIds
    ├── brand.repository.ts             # CRUD + findBySlug
    ├── product.repository.ts           # CRUD + paginate + images (child aggregate) + replaceAttributeValues + replaceRelated + soft delete
    └── product-variant.repository.ts   # CRUD + priceTiers (child aggregate) + findByIdWithProduct
src/modules/backoffice/
├── categories/   # BackofficeCategories{Module,Controller,Service} + categories.schemas.ts — دسته‌بندی + گروه‌های اتریبیوت + اتریبیوت‌ها
├── brands/       # BackofficeBrands* — برندها
├── products/     # BackofficeProducts* — محصول + تصاویر + مقادیر اتریبیوت + مرتبط‌ها + ساخت/ویرایش واریانت
└── inventory/    # BackofficeInventory* — موجودی/قیمت واریانت + پله‌های قیمت
src/modules/storefront/catalog/         # StorefrontCatalog{Module,Controller,Service} — خواندن عمومی
```

الگوها دقیقاً مطابق کد موجود: ریپازیتوری تایپ‌های Prisma برمی‌گرداند، `toView()` در سرویس، پاکت `Paginated<T> { items, total, skip, take }`، `paginate(where, skip, take)` با `$transaction([findMany, count])`، پیام‌های خطا فارسی، اسکیمای Zod با پیام فارسی و `z.string().length(24)` برای ObjectId.

## اندپوینت‌ها

**بک‌آفیس** (`/api/v1/backoffice/...`):
- **Categories** — `GET /categories` (لیست مسطح با عنوان والد + تعداد) و `GET /categories/tree` — `categories.view`؛ `POST`، `PATCH /:id`، `DELETE /:id` — `categories.manage`. حذف فقط وقتی فرزند/محصول نداشته باشد (Conflict). چرخه در والد (descendant check) رد می‌شود.
- **Attribute groups / attributes** — `GET/POST /categories/:categoryId/attribute-groups`، `PATCH/DELETE /attribute-groups/:id`؛ `POST /attribute-groups/:groupId/attributes`، `PATCH/DELETE /attributes/:id` — همه `categories.manage`. آپشن‌های select الزامی برای `inputType=select` (refine).
- **Brands** — `GET/POST /brands`، `PATCH/DELETE /brands/:id` — `brands.manage`. حذف با محصول متصل → Conflict.
- **Products** — `GET /products` (فیلتر: categoryId، brandId، isActive، isAmazingDeal، search روی title/slug + paginate) و `GET /products/:id` (کامل: واریانت‌ها، تصاویر، مقادیر اتریبیوت، برند/دسته) — `products.view`؛ `POST`، `PATCH /:id`، `DELETE /:id` (soft delete با deletedAt) — `products.manage`. به‌علاوه: `PUT /products/:id/images` (تعویض کل مجموعه)، `PUT /products/:id/attribute-values` (اعتبارسنجی attributeId متعلق به دسته محصول)، `PUT /products/:id/related`، `POST /products/:id/variants` (sku یکتا) و `PATCH /products/:productId/variants/:variantId` (فقط sku/colorName/isActive — `products.manage`).
- **Inventory** — `GET /inventory/variants?productId=&search=` و `PATCH /inventory/variants/:id` (فقط stockQty/priceOverride/isActive — `inventory.manage`)؛ `PUT /inventory/variants/:id/price-tiers`.

**فروشگاه** (`/api/v1/storefront/catalog/...`، همه `@Public` و فقط `isActive && deletedAt=null`):
- `GET /categories` — درخت فعال.
- `GET /brands` — لیست برندها (با `isExclusiveDistributor`).
- `GET /products` — فیلترها: category (شامل نسل‌های پایین‌تر — محاسبه در حافظه)، brand، minPrice/maxPrice، isAmazingDeal، search، فست اتریبیوت با `attrs=<attrId>:<value>,...` (ایندکس `[attributeId, value]`)، مرتب‌سازی `newest|price-asc|price-desc`، skip/take. هر آیتم: id، title، slug، basePrice، isAmazingDeal، برند، تصویر اصلی.
- `GET /products/:slug` — جزئیات کامل: محصول + واریانت‌های فعال (قیمت مؤثر `priceOverride ?? basePrice`) + تصاویر + مقادیر اتریبیوت + برند (با `authenticityNote` و `isExclusiveDistributor` برای نشان اصالت/نمایندگی انحصاری طبق بلوپرینت) + دسته + محصولات مرتبط فعال + datasheetUrl.

## سیم‌کشی و سایر تحویل‌دادنی‌ها

1. `app.module.ts` — افزودن ۵ ماژول جدید.
2. واحد تست‌ها به سبک `otp.service.spec.ts`: `products.service.spec.ts`، `categories.service.spec.ts`، `storefront-catalog.service.spec.ts`.
3. Postman — پوشه‌های Backoffice/Categories، Brands، Products، Inventory و Storefront/Catalog با بدنه نمونه، اسکریپت test و توضیح اسکما/پاسخ. اعتبارسنجی JSON.
4. `README.md` و `CLAUDE.md` در همان تغییر به‌روز می‌شوند.
5. Definition of done: `pnpm typecheck && pnpm lint && pnpm format:check && pnpm build && pnpm test` سبز.
